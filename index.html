Gelen Hata Mesajı Snippet'ı Neden Kaynaklanır? Çözüm Yolu
Cannot insert the value NULL into column 'ErkekMi'... column does not allow nulls. Tablo şemasında NOT NULL tanımlı sütuna değer gönderilmemiştir. INSERT sorgusuna ErkekMi değerini (1 veya 0) ekleyin.
Violation of PRIMARY KEY constraint 'PK_Ogrenci'. Cannot insert duplicate key value (389111). Tabloda zaten var olan bir Primary Key (Öğrenci No) tekrar eklenmeye çalışılmıştır. Benzersiz yeni bir OgrenciNo kullanın veya var olanı UPDATE edin.
The INSERT statement conflicted with the FOREIGN KEY constraint. Ana tabloda (Ogrenci) var olmayan bir OgrenciNo ile detay tabloya (OgrenciAdres) kayıt eklenmeye çalışılmıştır. Önce Ogrenci tablosuna kayıt açın veya Referans Bütünlüğünü kontrol edin.
The transaction log for database 'X' is full due to 'LOG_BACKUP'. Full recovery modelindeki veritabanının LDF log dosyası dolmuştur. Log yedeği alın (Shrink/Backup) veya Simple Recovery moduna alın.

DROP vs TRUNCATE vs DELETE

  • DELETE: DML komutudur. Satır satır siler, LDF'ye tam log tutar, WHERE alabilir. Yavaştır ama geri alınabilir.
  • TRUNCATE: DDL komutudur. Tüm tablo içeriğini tek hamlede boşaltır. Identity sıfırlar. Çok hızlıdır, WHERE alamaz!
  • DROP: DDL komutudur. Tabloyu yapısıyla (şema), verisiyle ve indeksleriyle birlikte tamamen yok eder.

CHAR vs VARCHAR vs NVARCHAR

  • CHAR(n): Sabit uzunluk. 11 haneli TC No için ideal. Girilmeyen yerler boşlukla doldurulur.
  • VARCHAR(n): Değişken uzunluk. Girilen karakter kadar yer kaplar + 2 byte başlık.
  • NVARCHAR(n): Unicode destekli (Türkçe, Çince). Her karakter 2 Byte yer kaplar! Kurumsal standarttır.

Üç Seviyeli ANSI-SPARC Mimarisi & Veri Bağımsızlığı

1. Dış Seviye / Görünüm (External / View Level)

Kullanıcının gördüğü kişiye özel sanal tablolar (VIEW). Yetkisi dışındaki sütunları gizler.

Kullanıcı Arayüzü
↑ ↓ Mantıksal Veri Bağımsızlığı (Tabloya yeni sütun eklense de dış görünüm kırılmaz!)
2. Kavramsal Seviye (Conceptual Level)

"Hangi veriler ve ilişkiler saklanıyor?" Mantıksal şema, tablolar, Primary/Foreign Key'ler burada tanımlanır.

Mantıksal Şema
↑ ↓ Fiziksel Veri Bağımsızlığı (Diski SSD'ye taşısak da mantıksal tablo yapısı etkilenmez!)
3. İç Seviye / Fiziksel Seviye (Internal / Physical Level)

Verinin diskte nasıl saklandığı, indeksleme teknikleri, Page ve Extent yerleşimi.

Disk & Donanım

MS SQL Server 4 Sistem Veritabanı

1. Master: Sistemin kalbi / Nüfus kütüğü. Tüm kullanıcı loginleri, veritabanı konumları buradadır. Bozulursa sunucu HİÇ AÇILMAZ!
2. Model: Şablon fabrikası. `CREATE DATABASE` dendiğinde tüm ayarlar buradan kopyalanır.
3. MSDB: SQL Server Agent (Otomasyon). Zamanlanmış görevler, otomatik yedekleme ve uyarı kayıtları tutulur.
4. TempDB: Ortak geçici çalışma masası. Sıralama ve JOIN işlemleri yapılır. Sunucu yeniden başladığında SIFIRLANIR!

Fiziksel Dosya Mimarisi & Boyutlar

.MDF (Primary Data File) Ana Veri Dosyası (Tablo, İndeks)
.LDF (Log Data File) Transaction Kara Kutusu (Kurtarma)
.NDF (Secondary Data File) İkincil Ek Veri Dosyaları

📐 Page (Sayfa): En küçük atomik veri birimi = 8 KB

📦 Extent: 8 adet Page = 64 KB (Diskten yer Extent olarak ayrılır!)

Write-Ahead Logging (WAL) & Checkpoint Mekanizması Simülatörü

1. Sorgu Geldi

UPDATE komutu çalıştırılır.

2. RAM (Buffer Pool)

Sayfa RAM'de güncellenir → Dirty Page oluşur.

3. LDF (Log) Yazımı

Değişiklik **önce** diske .LDF dosyasına yazılır! (WAL)

4. Checkpoint Process

Dirty Page fiziksel olarak .MDF dosyasına basılır.
